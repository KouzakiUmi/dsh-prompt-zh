# 设置页与译文条目

## 产品范围

设置页使用 DSH 原生 `settings.section` 扩展与当前 Profile 的配置表单。每个内置译文具有稳定条目 ID，显示所属组件、匹配方式、版本证据与插件阶段的处理结果。编辑框默认使用内置中文译文；保存的是该条目的译文覆盖值，不允许修改原文匹配规则或执行自定义代码。

- 组件可独立关闭；关闭后对应文本保留原文。
- 配置保存到当前 Profile 的 `prompt-zh` 配置项，使用宿主的 volatile 配置与修订号校验。
- “还原”仅将编辑草稿恢复为内置默认值与默认组件开关；点击保存后才写入 Profile。
- 动态模板的捕获占位符可以移动，但不能删除或改成其他捕获值；实际时间、路径等动态值不写入诊断。
- 保存时明确区分“宿主接受写入”和“之后实际命中并替换”；保存失败保留草稿，不显示成功。
- 对带工具句子关联的段落，当前工具集不满足关联条件时，本次渲染临时使用内置译文再裁剪，避免自定义措辞绕过可见性保护。保存值与条目 ID 不变；关联工具齐全时继续使用自定义译文。设置页单列内置回退次数。

## 版本门控与证据

第三方规则只在当前解析包版本与已核验精确版本一致时参与翻译。未核验、版本不符或版本不可读取均保留原文，不根据相似版本号放行。

已核验的第三方文本基线包括 `dsh-gitbash-shell` 0.39.0／0.39.4／0.42.2／0.43.2，以及 `@vectorize-io/hindsight-coding-agents` 0.8.1／0.8.2 的已知包装规则。Git Bash 的 `run_code` 提示与 0.42.2 起重写的执行通道路由分别属于对应版本，不混用转换语义；0.43.2 已逐条比对实际安装副本。

版本通过宿主的 Profile／插件包解析服务读取。它证明当前解析包的 manifest 版本，不冒充进程中旧模块已重载。MCP 服务器没有可核验的版本来源时显示“版本不可核验”，不把 MCP 客户端版本当作服务器版本；已知 server 的译文按每条原文特征守卫，仍在版本不可核验时执行，未命中的原文保持英文，未知 server 的标题与正文不翻译。

## 状态口径

- **版本**：精确一致／不一致／不可核验。
- **匹配方式**：固定原文、正则模板、section 名或生成条件；不把正则命中、名称匹配表述为全文逐字一致。
- **处理**：尚未观察／命中／输出已改变／被组件或版本门控阻止。
- **覆盖阶段**：系统组装、pre-step 消息或工具附加说明；分别累计阶段计数，所有统计仅代表插件观察到的阶段。
- **规则级阻止**：已进入条目替换点、但条目版本不符时的计数；组件关闭或整个版本门控未放行时不运行匹配，零计数不表示已放行。
- **内置回退**：关联工具缺失时，本次渲染未使用自定义译文的次数；不表示保存值被还原。Blender 已中文化标题重入不再虚增“输出改变”。

配置读取失败或旧覆盖值包含未知条目／字段时，运行时停译并标记配置无效，不擅自迁移或丢弃用户数据。能打开设置表单时可还原草稿并保存；若旧配置导致插件无法加载，应先在宿主原生插件配置中恢复默认后再进入设置页。

当前 Core 的 `refreshContext` 会在插件处理后重新生成部分 runtime-context。设置页对这类条目显示刷新重建说明：已保存译文挂在插件自有条目上，宿主重建后仍保留中文；快照标题句与 required 上下文（工作目录、团队身份）由宿主生成，不在插件条目内。诊断仍不能显示“最终请求已生效”——宿主后续重建、网关追加或远端追加的边界依然存在。

## 数据与接入

客户端不使用浏览器存储替代 Profile 保存。配置写入复用 `configForms`；诊断读取复用宿主已认证的 `connection.fetch` 扩展，不另建公开写接口。诊断只包含内置规则元数据、组件状态和计数，不保存会话原文、实际捕获值、完整提示词、凭据或本机路径。

无设置、连接或配置表单服务时，界面明确报告能力不可用；不显示虚假的保存成功。运行时监听、路由和 UI 注册均归插件生命周期管理。
